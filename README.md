# Ali Dentistry Care — Multilingual Conversion Blueprint

## Goal
Create a **high-converting multilingual dental website** for **Ali Dentistry Care (Tashkent)** where the primary funnel is:
**Search → Land → Trust → Book → Telegram data delivery**.

Default language is **Russian**. Supported languages: **RU / UZ / EN**.

## 4) Language Switch Behavior

## Required behavior
- Default language: **RU**
- Instant switch without full reload (preferred)
- Keep user in same section after switch
- Remember last language via `localStorage`
- Mobile-friendly dropdown switcher

## Recommended implementation (Option 1)
- Keep all translations in one JSON object
- Tag translatable elements with `data-i18n`
- On language change:
  1. Update text nodes from dictionary
  2. Update placeholder/label/button attributes
  3. Persist selected language

### Example dictionary structure

```json
{
  "ru": {
    "hero.title": "Профессиональная стоматология в Ташкенте",
    "hero.subtitle": "Безболезненное лечение и современный подход",
    "cta.primary": "Записаться сейчас"
  },
  "uz": {
    "hero.title": "Toshkentda professional stomatologiya",
    "hero.subtitle": "Og‘riqsiz davolash va zamonaviy yondashuv",
    "cta.primary": "Hoziroq yozilish"
  },
  "en": {
    "hero.title": "Professional Dentistry in Tashkent",
    "hero.subtitle": "Pain-free treatment with modern technology",
    "cta.primary": "Book Now"
  }
}
```

## Alternative implementation (Option 2)
- Separate pages:
  - `/ru`
  - `/uz`
  - `/en`
- Add `hreflang` tags for SEO
- Keep same section order and visual pattern in all language versions

## 5) Developer Notes (Simple, Fast, Conversion-Oriented)

## Stack strategy
- Webflow localization **or** static HTML/CSS/JS with JSON i18n
- Keep page lightweight (optimize images, lazy-load below fold)
- Preload hero image + critical fonts only

## Booking pipeline (do not overcomplicate)
1. User submits form
2. Frontend posts to webhook
3. Make.com receives payload
4. Make.com sends normalized message to Telegram

## Telegram message format (single format for all languages)
Use one fixed payload schema:
- `name`
- `phone`
- `service`
- `date`
- `language`
- `source` (e.g., `website_hero` or `website_booking_section`)
- `timestamp`

## Data/UX rules
- Validate phone input by region pattern (+998…)
- Mark only essential required fields
- Show instant success/error feedback near form submit button
- Fire conversion events:
  - CTA click
  - Form start
  - Form submit success
  - Telegram click

## SEO and localization notes
- If one-page dynamic i18n: keep key metadata localized where possible
- If split pages: configure unique title/description per language + `hreflang`
- Default canonical should point to primary RU page

## Content/media operations
- Source real photos from clinic Instagram and internal archives
- Use consistent lighting/editing style for professional trust
- Avoid generic stock model imagery
